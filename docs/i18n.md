# Translations (i18n)

The website ships in four languages. English is the source; every other
language must be complete before anything ships.

| Locale | URL prefix | `<html lang>` | `og:locale` | Address |
|---|---|---|---|---|
| English (source) | none: `/pricing` | `en` | `en_GB` | British English |
| Português (Brasil) | `/pt-br/pricing` | `pt-BR` | `pt_BR` | você |
| Deutsch | `/de/pricing` | `de` | `de_DE` | Sie (formal) |
| Français | `/fr/pricing` | `fr` | `fr_FR` | vous |

English URLs never change: every existing link, ad landing page and UTM keeps
working. `/en/...` permanently redirects to the unprefixed URL.

## Rules

1. **No visible string in components.** Copy lives in the dictionaries
   (`src/i18n/`). Text, `aria-label`, `alt`, `title`, `placeholder`, metadata
   and validation messages included.
2. **English is the type.** Each other locale is typed against the English
   dictionary, so a missing or extra key, or a list of a different length,
   fails `tsc` and the build. Numbers are literal types and cannot drift.
3. **Ids never translate.** Slugs, ids, hrefs, icons, image paths and
   anything sent to the APIs stay identical in every language
   (`pnpm i18n:check` compares them). Form answers reach sales as ids.
4. **Every internal link is localised** with `localePath(lang, path)` or
   `<LocalLink>`; never write `href="/…"` for a page.
5. **No new cookies or storage.** The language lives in the URL only. The
   language suggestion remembers a dismissal in memory for the visit.
6. **Never redirect by language.** Visitors whose browser prefers another
   supported language get a small suggestion; URLs, ad landings and UTMs
   are never changed automatically.
7. **The query string travels.** The language selector keeps `utm_*`, click
   ids and the hash, so attribution is identical in every language.

## Guard: nothing incomplete ships

| Gate | What it catches | When |
|---|---|---|
| `tsc` (dictionary types) | missing, extra or reshaped keys | `pnpm build`, pre-push |
| `pnpm i18n:check` | untranslated strings, changed ids/numbers/links, placeholder mismatches, hardcoded component strings, unlocalised links, uncovered mockup text, French typography | `prebuild` (so Easy Panel's build fails), pre-push |
| `pnpm i18n:layout` | text overflow, horizontal scroll and broken controls at 390/768/1440 px in every language | before shipping UI changes (needs Chrome) |
| `pnpm i18n:flow` | UTM capture, consent-gated cookies, lead and booking payloads, events, staying in language | before shipping anything touching tracking or the demo flow |

Because `prebuild` runs inside the Docker build, a push with an incomplete
translation fails the Easy Panel build and production keeps the previous
version.

## Writing translations

- Translate meaning and tone, not words: each language should read as if it
  had been written in it. Keep the brand voice: direct, concrete, no hype.
- Glossary and per-language typography: `docs/i18n-glossary.md`.
- Product feature names follow the app (`checkgrow-insight-hub/src/locales`)
  for German; the app's Portuguese is European, so Brazilian copy uses the
  glossary instead. French has no app equivalent yet; the glossary decides.
- Figures in customer stories keep their value; only the number format
  changes (US$307,650 → US$ 307.650 in pt-BR, 307.650 US$ in German,
  307 650 $ US in French).
- When a phrase does not fit its space, prefer a shorter natural phrasing
  over shrinking type; fix layout only when the language genuinely needs it.

## How copy reaches a component

```
src/i18n/
  config.ts              locales, localePath(), languageAlternates()
  dictionaries/en/*.ts   English copy, one file per namespace, `as const`
  dictionaries/<lang>/   the same files, typed Localized<typeof en.x>
  dictionaries/index.ts  getDictionary(lang) (server only)
  server.ts              setRequestLang(), getLang(), getT(ns)  (server components)
  client.tsx             <Messages>, useT(ns), useLang(), LocalLink, useLocalePath()
  metadata.ts            pageMetadata(lang, {path, title, description})
  format.ts              fmt("{n} of {max}", vars), plural(lang, n, {one, other})
```

**A page** (server):

```tsx
export async function generateMetadata({ params }: PageProps<"/[lang]/pricing">) {
  const lang = langOf((await params).lang);
  const t = getDictionary(lang).pricing;
  return pageMetadata(lang, { path: "/pricing", title: t.meta.title, description: t.meta.description });
}

export default async function PricingPage({ params }: PageProps<"/[lang]/pricing">) {
  const lang = langOf((await params).lang);
  setRequestLang(lang);                      // first thing: server components below read it
  const dict = getDictionary(lang);
  return (
    <Messages messages={{ pricing: dict.pricing, faq: dict.faq }}>   {/* only what the page's client components need */}
      <PricingSection />
    </Messages>
  );
}
```

**A server component** (no `"use client"`): `const t = getT("home").roles;`

**A client component**: `const t = useT("pricing");` (the page must provide the
namespace with `<Messages>`), `const lang = useLang()`, links with
`<LocalLink href="/book-a-demo">`, programmatic navigation with
`useLocalePath()("/demo-confirmation")`.

**Data modules** (`src/lib/*.ts`) keep types, ids and logic, take copy as an
argument, and never import dictionaries, so client components can use them.

**Interpolation**: `fmt(t.selected, { n, max })` with `"{n} of {max} selected"`.
Plurals: `plural(lang, n, t.people)` with `{ one: "{n} person", other: "{n} people" }`.
Rich text (a link or `<strong>` inside a sentence): split the sentence into
parts in the dictionary (`{ before, link, after }`) rather than HTML in strings.

**Dates and numbers**: `Intl` with `localeInfo[lang].tag` (English keeps
`en-GB`). Currency names: `Intl.DisplayNames`.
